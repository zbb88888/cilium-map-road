# cilium 图路 · 全景图（map）

> 项目顶层意图：**把 Cilium 建成一张完整的分层（分组件）架构地图；每个特性，都从地图里找出一条「路」。**
> 本目录 `map/` 是全景图；另一目录 `road/` 是每条路。

## 1. 两个目录，一个意图

| 目录 | 职责 | 产出一致性 |
| --- | --- | --- |
| `map/` | 完整架构地图：十面、每面的核心对象、对象间读者/写者关系、上下层上下文 | 稳态、全局唯一 |
| `road/` | 元素切面：把某个特性/某个对象跨层的交互串成一条路 | 一特性一路，从地图找路 |

> **找路流程**：拿到一个特性 → 在 `map/` 里定位它经过的层与对象 → 把跨层读写串起来 → 写成 `road/<feature>.md`。
> 例：`road/vni-ip-to-identity.md` 就是「(VNI,IP)→identity」这条路。

## 2. 地图怎么读

- **层（plane）**：业务内聚的状态域。谁写这块状态，谁就是归属层。
- **组件（component）**：装配/部署单元（daemon/operator/clustermesh-apiserver/hubble-relay + hive cell）。层与组件正交。
- **对象（object）**：层内 struct/interface/包函数，是读写动作的执行者。
- **边（edge）**：实线=写（写者→被写对象）；虚线=读（读者→数据源）。
- **承上启下**：每层读谁的什么状态（承上）、写谁的什么状态（启下）。

## 4. 图例约定（读虚写实）

- 写：实线 `-->` / `-->`，方向 = 写者 → 被写对象，标签 `写 xxx`。
- 读：虚线 `-.->` / `..>`，方向 = 读者 → 数据源，标签 `读 xxx`。
- 组合/归属（非数据）：`*--` / `o--`。
- 装配（依赖注入）：虚线标注 `装配`。

## 5. 找路规则（road 目录约定）

1. 一条路只讲一个特性或一个对象的跨层切面。
2. 起点/终点明确（例如：起点=CRD annotation，终点=flow vni_id）。
3. 用基线（原有实现）+ 增量（本特性改动）表达，标出每层改动的对象与文件。
4. 每段边沿用读虚写实，标 `写/读`。
5. 末尾给「地图坐标」：这条路经过了哪些层的哪些对象、对应哪些源码文件。

## 6. 顶层设计：完备性三问（每次看图/加对象必问）

> 这是 `cilium 图路` 的顶层验收门禁，落地在 [completeness.md](completeness.md)。

1. **当前一共有多少层，是否完备？** → 十面清单，每层独立 md + 七步模板。
2. **每一层有多少核心对象，是否完备？** → 每层对象清单，类型名对齐源码。
3. **每一个对象有多少读者、写者，是否完备？** → 无孤儿对象、无悬空状态、读虚写实边齐全。

> 三问逐级下钻：层 → 对象 → 读写边。任何一层/一对象/一条边不齐，地图就不算完备；
> 新增对象必须先回答：它属于哪一层、读谁、写谁。
